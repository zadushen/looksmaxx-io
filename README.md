# Looksmaxx.io

Игра: https://looksmaxx-io.onrender.com/ . Исходники: https://github.com/zadushen/looksmaxx-io .

Локальная мультиплеерная арена: сервер хранит единый мир (игроков, еду, ботов, массу, столкновения, смерть и респавн), а браузеры передают только ввод. Два игрока видят одну и ту же еду и результат каждого столкновения.

## Запуск

Нужен Node.js 22 или новее.

```bash
npm install
npm start
```

После запуска откройте на компьютере-хосте [http://localhost:3000](http://localhost:3000).

## Игра вдвоём в одной Wi-Fi сети

1. Подключите оба устройства к одной Wi-Fi сети.
2. На Mac, где запущен сервер, узнайте его адрес в сети:

   ```bash
   ipconfig getifaddr en0
   ```

   Если команда ничего не вернула (например, используется Ethernet), откройте «Системные настройки → Сеть» и возьмите IPv4-адрес активного подключения.
3. Друг открывает в браузере `http://ВАШ_IP:3000`, например `http://192.168.1.42:3000`.
4. Если macOS спросит про входящие подключения Node.js, разрешите их для частной сети. При необходимости проверьте, что порт 3000 не блокируется файрволом.

Сервер слушает `0.0.0.0`, а WebSocket-клиент строит адрес от `location.host`; поэтому URL с LAN-IP автоматически подключает игрока к тому же серверу, без изменения настроек.

## Публичный деплой: Render

Для первой публичной версии выбран [Render](https://render.com): он запускает постоянный Node.js web service, выдаёт HTTPS и принимает WebSocket-соединения. Файл `render.yaml` уже задаёт сборку (`npm ci`), запуск (`npm start`) и production-режим — отдельный reverse proxy не нужен.

1. Загрузите проект в новый Git-репозиторий на GitHub, включая `render.yaml` и `package-lock.json`.
2. Войдите в Render, нажмите **New → Blueprint** и подключите этот репозиторий. Render обнаружит `render.yaml`; подтвердите создание сервиса `looksmaxx-io`.
3. Дождитесь успешной сборки. В логах должна появиться строка `Looksmaxx.io running on http://localhost:...`.
4. Откройте URL сервиса вида `https://looksmaxx-io.onrender.com`. Его уже можно передавать игрокам. Свой домен при необходимости добавьте в **Settings → Custom Domains** и следуйте DNS-инструкциям Render.
5. Для текущего сервиса использован публичный URL репозитория без установки приложения Render в GitHub. После успешного CI обновление запускается через **Manual Deploy → Deploy latest commit**. Автодеплой по push для такого подключения не подтверждён; параметр Blueprint `checksPass` применяется при полноценном подключении Git-провайдера.

### Переменные окружения

`PORT` всегда читает сервер. Локально он по умолчанию равен `3000`; пример находится в `.env.example`:

```bash
PORT=3000 npm start
```

На Render не задавайте `PORT` вручную: платформа передаёт подходящее значение автоматически, а сервер слушает его на `0.0.0.0`. В Blueprint заданы несекретные настройки среды, версии Node.js, журналирования и лимитов. Сейчас приложению не нужны ключи, база данных или иные секреты.

Игра хранит мир и комнаты в памяти процесса, поэтому в `render.yaml` закреплён один экземпляр (`numInstances: 1`). Не увеличивайте число инстансов, пока не появится общее хранилище/координация матчей: при нескольких экземплярах Render может направить игроков одной комнаты на разные процессы.

### HTTPS и WebSocket

Публичная страница Render работает по HTTPS. Клиент выбирает `wss://` при `https:` и `ws://` только для локального HTTP, поэтому смешанный контент не возникает. Render поддерживает входящие WebSocket-подключения к тому же публичному порту, что и HTTP.

После создания сервиса откройте DevTools → Console на его `https://`-адресе: подключение должно появиться без ошибки `Mixed Content` или `WebSocket connection failed`. Для независимой проверки из терминала можно выполнить:

```bash
npx --yes wscat -c wss://YOUR-SERVICE.onrender.com
```

Успешное подключение и сообщение `welcome` подтверждают защищённый WebSocket. Не используйте `ws://` для публичного адреса Render.

Проект намеренно не содержит аккаунтов, базы данных и встроенного деплоя. Состояние матчей живёт в памяти процесса: перезапуск сервера очищает активные комнаты и арены.

## Проверка

```bash
npm test
```

Тесты проверяют серверную симуляцию, разделение и слияние, ускорение, смерть и респавн; клиентские снимки мира; клавиатуру, мышь и сенсорные действия; HUD, все тиры аватаров, загрузку PNG, резервную отрисовку и видимость объектов у границ экрана. Клиентские проверки используют модель DOM/canvas и выполняют настоящий код интерфейса и управления. Сетевые тесты запускают отдельный локальный сервер и проверяют HTTP, двух игроков в одной комнате и изоляцию арен. Для них среда должна разрешать локальные сетевые подключения. Визуальный внешний вид дополнительно проверяется вручную в браузере на компьютере и мобильном размере экрана.

Для быстрой ручной проверки после запуска откройте `http://localhost:3000`, а затем в отдельном терминале:

```bash
curl -I http://localhost:3000
curl -I http://localhost:3000/public/favicon.svg
```

## Подготовка выпуска

Требуется Node.js 22 или новее. Перед загрузкой:

```bash
npm ci
npm run check:release
npm run audit:network
npm run audit:arena
```

Сервер симулирует мир с частотой 20 Гц и отправляет снимки с частотой 10 Гц. Первый снимок содержит всю еду и карту; следующие — изменения еды и удаления. Клиент сглаживает движение. WebSocket-сжатие включено; медленному соединению с накопленной очередью отправляется полный снимок после восстановления.

Локальные ограничения по умолчанию: 64 игрока в общем мире, 12 в приватной комнате, 128 соединений на процесс и 32 арены. Публичный Render Free ограничен шестью соединениями суммарно и двумя аренами: общим миром и одной приватной комнатой. В каждой арене максимум шесть игроков, но общий лимит процесса также шесть. На соединение допускается 120 сообщений и 4 перехода между комнатами за секунду; максимальный входящий пакет — 4096 байт. При отсутствии ввода 500 мс движение и ускорение останавливаются. Ping/pong удаляет потерянные соединения. SIGTERM/SIGINT закрывает клиентов с кодом 1012 и завершает процесс. Проверка работоспособности: `/healthz`.

Состояние матча временное: после перезапуска комнаты и масса сбрасываются. Код `src/progress.js` не подключён к текущему игровому клиенту; аккаунтов и сохранённого игрового прогресса в этой версии нет. Для деплоя нужен один экземпляр сервера. Результаты локальной нагрузки не определяют вместимость конкретного тарифа хостинга.

После публикации обязательны проверка HTTPS/WSS на выданном адресе, матч с двух внешних устройств, проверка через мобильную сеть и физический телефон в обеих ориентациях. В случае ошибок отключите автодеплой, верните предыдущую версию и повторите проверку `/healthz` и подключения. Перезапуск сбросит активные матчи.

## Внешний релиз

Сценарий устройств: [artifacts/device-check.md](artifacts/device-check.md). Развёртывание и откат: [artifacts/deployment.md](artifacts/deployment.md). Проверка внешнего адреса: `node scripts/check-online.mjs https://ACTUAL-SERVICE.onrender.com`. Лимиты задаются `PUBLIC_LIMIT`, `ROOM_LIMIT`, `CONNECTION_LIMIT` и `MAX_ROOMS`; неверные значения останавливают запуск вместо отключения ограничений. Текущий Blueprint использует бесплатный тариф и консервативный лимит шесть подключений суммарно по результатам внешней нагрузки. Незашедшее в игру соединение закрывается через 10 секунд.

## Диагностика плавности

Откройте игру с `?debug=1`: панель показывает FPS, p95 интервала кадра, p95 времени render, паузы >100 мс, интервалы WSS и RTT. Это измерение текущего браузера, не FPS сервера. В скрытой вкладке сбор кадров сбрасывается. По обычному адресу панель и диагностические ping отключены.

Свой одиночный персонаж начинает визуальное движение до нового снимка; сервер плавно корректирует позицию. Предсказание ограничено свежими снимками (250 мс) и не определяет массу, поглощение или смерть. Для двух частей остаётся серверное сглаживание. Сценарий модели: `node scripts/audit-smoothness.mjs`; критерии проверки: `artifacts/GAME-QA.md`.
