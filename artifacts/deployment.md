## Первый запуск

- Один Node.js web service по `render.yaml`; база данных не нужна.
- Явный `plan: free`, регион Frankfurt, Node.js 22, health check `/healthz`.
- Blueprint содержит `checksPass`, но сервис подключён через публичный URL без приложения Render в GitHub. Обновления выполняются вручную после успешного CI; автодеплой по push не подтверждён.
- Ограничения Render Free: PUBLIC_LIMIT=6, ROOM_LIMIT=6, CONNECTION_LIMIT=6, MAX_ROOMS=2. Шесть подключений суммарно; общий мир и одна приватная комната.
- Не добавлять способ оплаты и не переключать тариф без участия пользователя.
- Бесплатный сервис засыпает после 15 минут без входящего HTTP/WS-трафика, холодный запуск занимает около минуты: https://render.com/docs/free . Перезапуск/засыпание сбрасывает комнаты и массу.

## Проверка внешнего адреса

```bash
node scripts/check-online.mjs https://ACTUAL-SERVICE.onrender.com
# Общую арену нагружать только до приглашения реальных игроков:
LOAD_ROOM=public node scripts/check-online.mjs https://ACTUAL-SERVICE.onrender.com
```

Проверка использует WSS, сверяет PNG с локальными, создаёт временную комнату, проверяет движение и повторный вход, затем постепенно подключает 1/2/4/6 клиентов. При плохих интервалах снимков прекращает рост нагрузки. Вывод — `artifacts/online-audit.json`.

Считать этап нагрузки прошедшим, если все соединения открыты, каждый клиент получил минимум 7 снимков/сек и 95-й процентиль интервала меньше 200 мс и скорость симуляции минимум 0,9 от реального времени. Это критерий теста, не гарантия для всех сетей и тарифа. Дополнительно проверить логи CPU/RAM в панели; подобрать PUBLIC_LIMIT по фактическим результатам и повторить проверку. Первый прогон выполняется в собственной тестовой комнате. Общую арену проверить отдельным прогоном до приглашения реальных пользователей; результаты сохраняются отдельно в `online-public-audit.json`.

Перезапуск проверять только после предупреждения активных тестировщиков: все текущие матчи сбросятся. После него `/healthz` возвращает 200, WSS подключается, старые коды приватных комнат не работают. Физические устройства проверяются по `device-check.md`.

## Откат

1. В Render отключить автоматический деплой, чтобы новый коммит не заменил выбранную версию.
2. Открыть историю Deploys и выбрать последнюю подтверждённую исправную версию. Для первого деплоя предыдущей версии нет: исправить текущую сборку или приостановить сервис.
3. Выполнить Rollback только после предупреждения тестировщиков; перезапуск очищает матчи. Бесплатный тариф ограничивает откаты двумя последними предыдущими деплоями.
4. Проверить `/healthz`, главный экран, WSS, вход двух игроков и создание комнаты. Записать commit SHA и результат в RELEASE.md.
5. Исправление подготовить отдельным коммитом; вернуть автодеплой после успешных проверок.

Документация: https://render.com/docs/blueprint-spec , https://render.com/docs/free .

## Обновление конфигурации

После успешного GitHub CI для изменения render.yaml откройте Blueprint → Manual sync, проверьте список изменений и Approve. Синхронизация применяет переменные и запускает обновление. Для изменения только кода используйте Manual Deploy → Deploy latest commit. Проверьте Live и SHA коммита; один push не подтверждает публикацию.

При откате сохраняйте лимиты 6/6/6/2. Предыдущий код 659c948 не читает ROOM_LIMIT, поэтому вместимость приватной комнаты в нём 12, но глобальный лимит шесть продолжает ограничивать подключения. Не откатывайте расширенные лимиты из старого Blueprint одновременно с кодом.
